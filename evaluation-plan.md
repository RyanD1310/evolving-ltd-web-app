
# Evolving Ltd – Evaluation Plan

## 1. Purpose

This plan explains how the final web application and automation will be tested against Evolving Ltd's business requirements.

## 2. Evaluation Criteria

| Business Requirement | Testing Method | Expected Result |
| --- | --- | --- |
| Deployment speed | Measure deployment time | Under 20 minutes |
| Recovery | Simulate a deployment failure and measure recovery time | Under 10 minutes |
| Automated testing | Run automated tests against the application | Tests execute and report results |
| Security | Review credentials and access permissions | No exposed passwords or shared administrator accounts |
| Traceability | Review GitHub commits and pull requests | Changes are recorded and traceable |
| Reliability | Test how the application responds to failures | Failures can be identified and investigated |
| Environment consistency | Compare development and test configurations | Consistent configuration across environments |

## 3. Functional Testing

Test that the website loads correctly, displays the customer enquiry form and accepts user input. Test form submission and validation once implemented.

## 4. Automated Testing

Develop and run automated tests to check important application functionality. Record successful tests and failures.

## 5. Security Testing

Review the application to ensure sensitive information is protected and access permissions are appropriate.

## 6. Evidence Collection

Collect screenshots of the website, GitHub commits, pull requests, automated test results and deployment timings.

## 7. Final Evaluation

Compare the test results against the business requirements. Document any unsuccessful tests, limitations and recommended improvements.
